# The Open Wild Thingz — Tool Archaeology & Composition Engine

A run of the four-tier discovery pipeline: unearth genuinely obscure open-source tools
across a wide domain grid, verify them against real repos, then invent non-obvious ways to
**chain two or more of them** so the combination does something none does alone.

> **Novelty bar for this run:** *maximize weird*. A brilliant improbable combo beats a safe
> practical one. Feasibility is a tie-breaker, never a gate.

---

## How this was produced (orchestration)

This is not a hand-written list. It was generated by a deterministic four-tier fan-out,
with the orchestrator (Fable 5) owning the plan, the triage, and the final adjudication:

| Tier | Model | Job | Fan-out |
|------|-------|-----|---------|
| **Skimmer** | Haiku 4.5 | Read-only sweep of awesome-lists / package indexes / search pages; extract unverified candidates | 23 agents, ≥1 per grid cell + 2 artifact-reservoir scouts |
| **Orchestrator triage** | Fable 5 (code) | Dedup by repo, cap ≤3 tools/field (dense-domain discipline), ceiling the shortlist | continuous |
| **Worker** | Sonnet 5 | Open each repo; confirm existence, stars, license, last-commit, **actual** glue | 14 verify batches |
| **Reasoner** | Opus 4.8 | Compose emergent chains, self-score against the novelty rubric + Wild-but-Good filter | 4 mandates × 5 chains |
| **Orchestrator adjudication** | Fable 5 | Cut secretly-obvious & dumb-wild, merge near-dupes, enforce quotas, rank, report | final |

**Run stats:** 41 agents, 0 errors · **296** unique candidates skimmed · **54** shortlisted ·
**52** verified real · **20** chains composed → **15** distinct chains kept + 5 folded variants.

### Verification honesty (read this before trusting a number)

- **Stars / last-commit are approximate**, captured during the run (July 2026). GitHub's API
  was intermittently blocked by the environment proxy, so several values are marked `unknown`
  rather than guessed.
- **Skimmers guess repo URLs; workers corrected many.** Real corrections this run:
  CG-3 is `GrammarSoft/cg3` (not `visl/constraint-grammar`), Nanocubes is `laurolins/nanocube`
  (not `nano-db/NanoCube`), bifrost is `aperturerobotics/bifrost` (not `pojntfx/bifrost`),
  famfs is `cxl-micron-reskit/famfs`, fx2lafw is `sigrokproject/sigrok-firmware-fx2lafw`.
- **No invented flags.** Where a command's exact syntax wasn't confirmed against docs, the
  sketch says **"see docs"** instead of fabricating flags. `colibri-patternmodeller` and
  TauDEM's `pitremove`/`dinfflowdir`/`areadinf`/`streamnet` were spot-verified as real
  command names; their exact single-letter flags for skipgrams/thresholds are left to docs.
- Each chain carries a **confidence** label: `verified` (mechanism confirmed) /
  `plausible` (interop inferred from how the tools work) / `speculative` (untested idea).

## Domain grid coverage

Tools were pulled from **19 distinct fields** (target was ≥12), deliberately spanning fields
far apart on the grid — because the best cross-domain chains come from pairing tools whose
native domains are nowhere near each other.

`text/NLP & linguistics` · `data/analytics & viz` · `mapping/GIS & hydrology` · `bio/chem` ·
`audio/DSP` · `image/graphics` · `video` · `3D/CAD` · `scientific/simulation` · `networking` ·
`security/forensics (defensive)` · `hardware/SDR/embedded` · `game/emulation & preservation` ·
`docs/publishing & literate` · `filesystems/storage` · `retro/esoteric & notation` ·
`OSINT/recon (research)` · `public feeds/archives` · `firmware`.

**Artifact-type spread** (the second axis — *what kind of thing*, not just what field):
`tool` · `firmware` · `notation/DSL` · `public-feed` · `dataset` · `ML model` · `GUI app` ·
`rule/grammar engine`. ≥7 types represented; **6 of 15 chains are artifact-crossing**
(pair a tool with a non-tool artifact).

### 1. The Grammarian's Wiretap — *weighted 45.5* 🏆
**Tools:** `netsniff-ng` (source) → `awk` (adapter) → **CG-3** (daemonized rule engine / sink)
**Domains bridged:** rule-based computational linguistics ✕ network security
**The glue:** `netsniff-ng` prints per-packet dissection on stdout → `awk` rewrites each packet
as a CG-3 **cohort** (a surface token + a bag of tags: proto / flags / port) → `vislcg3 -g`
runs a constraint grammar as a **long-lived stream filter**, applying context-dependent rules
that reason *across* packets at variable distance, emitting a tagged alert stream.
**What no single tool does:** you write TCP-flow intrusion logic as *linguist-style context
rules* — "this packet is benign only if no RST intervened since the SYN N cohorts back" — getting
cross-packet stateful reasoning with **zero imperative code**.
**Sketch:**
```sh
netsniff-ng -i eth0 --notouch-irq 2>/dev/null \
  | awk -f pkt2cohort.awk \
  | vislcg3 -g flow.cg3 > /var/log/flow-alerts
# flow.cg3:  REMOVE (@benign) IF (-2 ("tcp" SYN)) (-1 ("tcp" SYNACK)) (0 ("tcp" ACK)) ;
#   -g/--grammar is verified; cohort format & rule syntax per cg3 docs
```
**Pattern:** sidecar / daemonize + rule-engine repurposing · **Scores:** [5·5·5·4·3] → **45.5**
**Verdict:** **good-wild** — a constraint-grammar disambiguator doing stateful packet-flow
classification is a genuine idea-collision, not plumbing; audience is DFIR/SOC engineers who want
declarative, human-auditable, order-sensitive multi-packet rules.
**Fragile seam:** `netsniff-ng`'s dissection is human-readable, not a stable machine format, so
the `awk` cohort-izer is brittle; CG-3 assumes in-order tokens, so any reordering/drop corrupts
the "sentence." **Effort:** an afternoon. **Confidence:** plausible.
**Variant (folded):** *Grammar of Packets* extends the sink into **Siembol** (parse tags back to
JSON → Kafka) for enterprise-scale alerting.

### 2. Rivers of the Face / Watershed of Meaning — *weighted 44 / 42.5* 🏆
**Tools:** `imagemagick` (adapter) → **TauDEM** (transform) → `pixelsort` *or* **SedonaDB** (sink)
**Domains bridged:** hydrology / terrain analysis ✕ glitch art *and* ✕ ML/analytics
**The glue:** `magick` converts luminance to a 32-bit floating-point grayscale **GeoTIFF** (a
fake DEM) → TauDEM's MPI chain runs pit-removal → D-Infinity flow direction → flow accumulation,
treating brightness as elevation → the extracted **stream network / basins** are either rendered
as generative art (`pixelsort` along the drainage lines) or polygonized to GeoParquet and queried
in **SedonaDB**.
**What no single tool does:** real hydrological math (D-Infinity separatrices) applied to a photo
or an ML saliency/embedding raster yields either *hydrologically "true" fictional rivers of a
human face*, or a **deterministic, tuning-free hierarchical clustering** (basins nest; ridgelines
are exact cluster boundaries) that neither k-means nor a saliency tool produces.
**Sketch:**
```sh
magick portrait.jpg -colorspace Gray -depth 32 -define quantum:format=floating-point dem.tif
gdal_translate -a_srs EPSG:3857 -a_ullr 0 1000 1000 0 dem.tif geo.tif   # stamp a synthetic geotransform
pitremove   -z geo.tif -fel fel.tif
dinfflowdir -fel fel.tif -ang ang.tif -slp slp.tif
areadinf    -ang ang.tif -sca sca.tif                     # flow accumulation = river brightness
magick sca.tif -auto-level rivers.png && pixelsort rivers.png -o final.png
#   (analytics face: polygonize basins → SELECT ... FROM sedona.read_geoparquet('basins.parquet'))
```
**Pattern:** cross-domain repurpose (wrong-domain-as-substrate) · **Scores (art):** [5·5·5·3·2]
→ **44** · **(analytics):** [5·4·5·4·3] → **42.5**
**Verdict:** **wildcard** (art) / **good-wild** (analytics) — TauDEM has no notion of art *or*
clustering; the collision (luminance == elevation) produces imagery and partitions neither tool
could. For generative artists and cartography nerds, *and* for ML/vis researchers wanting exact,
parameter-light segmentation.
**Fragile seam:** the fabricated GeoTIFF must carry a valid geotransform with sane pixel spacing or
D-Infinity slope angles distort / the MPI tools refuse; noisy rasters over-segment (pre-smoothing
is doing real work). **Effort:** an afternoon. **Confidence:** plausible (art) / speculative→plausible.

## Top 3 sleepers (most surprising these aren't better known)

1. **colibri-core** — a memory-efficient **flexgram** (variable-gap pattern) miner that turns out
   to be a general-purpose "find fixed-anchors-with-a-variable-body" engine. It anchors three of
   our chains (spaced DNA motifs, arcade-SRAM record grammars, byte-stream structure) and *none*
   of them is what it was built for. ~130★ is far too few for a tool this composable.
2. **VISLCG3 / CG-3** — a 20-year-old constraint-grammar engine at ~26★ that is, underneath,
   a declarative **pattern-over-variable-distance** solver with `BARRIER` operators. The moment you
   stop thinking "linguistics" and start thinking "stateful classification of any ordered token
   stream," it becomes a packet-flow IDS you write in rules instead of code.
3. **Nanocubes** — dormant since 2019, ~730★, but it's a billion-scale interactive OLAP surface
   that only asks for `lat, lon, time, category`. Any key space you can remap into coordinates
   (genome position, IPv4 via Hilbert curve, historical-photo years) becomes navigable at 60 fps.
   The remap trick deserves to be a standard pattern.

## Frontier notes (suspected-but-unverified — what I'd test next)

- **zindex over the genome/SRAM corpora.** `zindex` gives instant random access into *compressed*
  line-based text. Chains 4 & 6 build big byte/codon corpora; indexing them with zindex should let
  colibri's pattern lookups jump straight to occurrences without decompressing. *Test:* does
  colibri accept an externally-indexed corpus, or would this need a shim? (unverified)
- **f-rep CAD as an audio/terrain substrate.** `ImplicitCAD`/`LibFive` express geometry as pure
  math functions. A functional representation of a surface is *also* a 2-variable field — feeding a
  LibFive f-rep sampled to a raster into TauDEM (chain 2) would give exact, noise-free "watersheds
  of a mathematical object," and the same f-rep evaluated over time could drive FM synthesis
  parameters. Completely un-tried; the seam is the sampling step. (speculative)
- **weron/bifrost carrying the Nallely bus.** Nallely's live-coding runs over a WebSocket bus;
  tunnel that bus through `weron`'s WebRTC overlay and you get **distributed, NAT-punching
  collaborative live-coding** across machines with no central server. Both halves are verified real;
  the composition is untested. (plausible)
- **dwarf2json → grammar miner.** `dwarf2json` emits structured ISF JSON of kernel symbols; pointing
  a skipgram/grammar miner at *layout regularities across many kernels' ISF* might surface struct-
  packing conventions. Weakly motivated but cheap to try. (speculative)
